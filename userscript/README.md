# AIHubRouter 油猴版 0.1.11

独立运行在 `https://aihub.top/*` 的网站内面板，复用扩展 0.3.21 的路由、改组流程与监控界面。

## 安装与入口

1. 在 Chrome 或 Edge 安装 Tampermonkey，并按其提示允许用户脚本运行。
2. 打开 Tampermonkey 的“添加新脚本”，将本目录 [AIHubRouter.user.js](AIHubRouter.user.js) 的**全部内容**替换进去，保存。文件本身为可安装的标准 `.user.js`，不依赖远程代码。
3. 登录 [AIHub](https://aihub.top)，刷新页面。右下角出现 **↗ AIHubRouter**；Tampermonkey 菜单也可打开面板。
4. 在“配置”点击“读取 key 与模型”，选择 key 和完整模型名并保存。初次默认**仅预览**。
5. “监控”中查看建议和合格候选，需要时明确打开该 key 的自动切换。手动切换须确认，确认后暂停该 key 的自动选择。

请勿同时使用扩展版和油猴版自动管理同一个 key；两个产品的配置和锁相互独立。旧扩展配置不会自动导入。

## 运行与安全边界

- 至少保留一个 AIHub 标签页。收起面板继续运行；所有网站页面关闭后停止。后台节流、电脑休眠、页面冻结可能延后检查，不承诺精确每分钟运行。
- 默认 5 分钟，可设 1–60 分钟；各标签页共享最近尝试时间。失败也按间隔重试，不补发积压检查。
- 使用浏览器 Web Locks 对所有读写操作串行加锁，自动轮询以非阻塞方式竞争同一把锁。一页冻结并持锁时其他页等待，防止锁超时带来重复写入；关闭该页由浏览器释放锁。浏览器不支持此能力时禁止执行。
- 配置、账号 ID、有限日志和待核实 from/to 意图存在 Tampermonkey 私有存储，同一脚本的标签页共享。卸载脚本时可删除这些数据。
- 只读取网站当前 `auth_token` 用于同源请求，不把登录令牌、完整 API key、密码或刷新令牌写入脚本存储。日志使用数字 key ID，不记录认证头或响应正文。
- 每轮核对账号，写入前再次核对账号与当前分组；等待异步存储保存操作意图成功后才写入，存储失败不提交改组，写后读回。未知结果先核实，不重放。账号变化后暂停全部监控，移除旧监控并清空账号绑定后再连接。
- “断开并暂停”跨标签页、刷新和重启保留；“读取 key 与模型”明确重新连接。不会退出网站自身登录。
- 提醒显示在面板的状态与“记录”中；不申请系统通知权限。建议定期查看面板。
- 平台没有已确认的条件写入接口，其他客户端仍可能在最后读回与写入之间改组；无法提供跨设备事务保证。平台故障转移设置保持原样。

规则见 [完整路由规则](../docs/routing.md)。模型目录动态读取。模型价格缺失时，符合其余条件的渠道仍列入合格候选，并展示可用的 1× 渠道价。设置最高模型价格时，缺价渠道列在「未参与比较」。

## 开发与验证

在仓库根运行：

```sh
npm run build:userscript
npm test
npm run check
npm run test:userscript
```

`scripts/build-userscript.mjs` 从 `extension/core.js`、`background.js`、`options.*` 与 `userscript/runtime.js` 生成单文件，修改源文件后必须重新构建。不要直接改生成文件。构建不读取 HAR、真实账号数据或 work 目录。

浏览器验证仅使用隔离 Edge 配置和拦截的模拟接口；GM 存储使用测试替身。覆盖界面绑定、默认预览、双标签互斥、未知写入读回、拒绝重放、账号变化、断开持久化及窄屏布局。真实 Tampermonkey 安装和真实账号改组仍需用户自愿验证，不能据此声称已在真实账户验证。
