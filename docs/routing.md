# 排序、筛选与切换规则

返回 [项目首页](../README.md)。

## 已实现的规则

- 默认每 5 分钟检查一次，可设置1–60分钟；电脑休眠、浏览器节能等可能延后检查，唤醒后不会补发多次请求。
- 分组须位于当前账号的可绑定列表中，绑定模型须在分组模型列表中明确列出，并有未过期的 healthy 模型卡。大厅可见性不参与路由筛选。平台开启模型探测或省略旧分组探测状态时，使用所选模型卡判断健康状态。需要旧版分组探测的数据仍校验分组的可用状态和探测有效期。默认还要求渠道的“模型检测通过”，此项可开关。
- 排序方式有三种：模型价格、综合排序、自定义。模型价格已包含账号倍率和缓存率。每个 Key 保存自己的策略，在监控卡片调整。新建 Key 默认复制配置页的策略模板。
- 正常优化时，同一候选须在连续指定轮数的检查中均为当前策略最优（默认一轮）。立即检查不会加速确认；漏掉一轮、读取失败或更换策略会重新计数。同分保留当前分组；模型价格模式即同价不切。
- 当前分组不合格时，在下次检查立即选合格的策略最优候选；无合格候选保留当前并提醒。
- 平台内置故障转移保持原样，实际请求仍可能被平台路由到其他分组。
- 发现外部改组时更新分组记录并重置确认计数，本轮不改组，下轮继续监控。
- 浏览器通知及插件内记录；相同故障去重。读取失败下轮重试，登录失效等用户重新登录。
- 配置页可开启「无法连接时自动打开供应商页面」（默认关闭，仅扩展版）：检查或读取 key 与模型时发现网站登录会话缺失（含身份校验之后的接口返回登录失效），在后台标签页打开 https://aihub.top/providers；已有 AIHub 页面时不打开，最多每 10 分钟一次。
- 切换前持久记录 from/to，切换后读回。结果不明先核实；如果仍在原分组则暂停，出现第三个分组则更新记录并等待下轮，避免盲目重复写入。
- 账号变化时暂停所有监控，必须移除旧配置并清空账号绑定，才能连接新账号。

## 排序策略与自定义规则（0.3.0）

初始模板为综合排序。创建监控时复制当时的默认策略，模板改动只用于之后新建的 Key。旧版升级时，已有 Key 保存各自当时生效的策略。

| 因素 | 数据来源 | 方向 |
|---|---|---|
| 模型价格 | 指定模型输入和输出标价，按下方公式加权并乘账号倍率 | 越低越好 |
| 首响应延迟 | 指定模型 1h 摘要的 `user_latency_ms` | 越低越好 |
| 成功率 | 指定模型 1h 摘要的 `success_rate` | 越高越好 |
| 消费排名 | 平台同类分组的消费名次，按「名次 ÷ 同类分组数」比较，须在有效期内 | 越靠前越好 |
| 用户评分 | 渠道的用户评分星级（`reputation.stars`） | 越高越好 |

模型价格（美元／百万 Token）=（比例 ×［(1 − 命中率) × 输入标价 + 命中率 × 缓存输入标价］+ 输出标价）÷（比例 + 1）× 账号倍率。标价取绑定模型在 `group_models` 中的 `input_per_million`、`cache_input_per_million`、`output_per_million`；渠道未列缓存价时缓存读取按输入价计，输入或输出标价缺失时视为价格缺失。比例（输入∶输出 Token，默认 3∶1）和缓存命中率假设（默认 80%）在每个 Key 的策略里设置；默认开启“有实测数据时用各渠道的 1h 缓存命中率”，渠道缓存数据未就绪或过期时才用假设值。缓存写入及长上下文溢价不计入。

模型价格缺失时，通过健康、可用、权限和其他策略检查的渠道仍可入选。价格参与排序时，有价渠道优先。当前渠道可用但缺少价格、其他候选有价时继续使用。纯价格策略在全部合格候选缺价时按账号倍率从低到高选择，同倍率保留当前渠道；确认轮数、冷却和最小改善幅度继续生效，改善幅度按账号倍率降幅计算。账号倍率无效的渠道不作为回退切换目标，当前渠道可用但账号倍率未知时保留当前。加权策略在所有候选缺价时按其余已配置的权重排序。延迟和成功率参与策略时仍要求对应数据。

编辑策略时权重区一直显示：选择模型价格填入价格100，选择综合排序填入它的预设权重，选择自定义填入该 Key 上次保存的自定义权重。改动任一权重即切换为自定义。权重范围0–100，总和无需为100，按总和自动换算。自定义模式下，消费排名或用户评分权重大于0时，缺少对应数据（消费名次未知或已过期、没有评分）的渠道不参与比较。每项指标在本轮合格候选中按最小/最大值换算为0–100分：

- 价格、延迟、消费排名（名次占比）：`100 × (最大值 − 当前值) / (最大值 − 最小值)`。
- 成功率、用户评分：`100 × (当前值 − 最小值) / (最大值 − 最小值)`。
- 全部候选同值时该项均为100分；最终分数为各项按权重的加权平均。

「综合排序」是固定预设：模型价格40、成功率25、首响应延迟15、用户评分10、消费排名10，打分方式同上。成功率和延迟为必需数据；用户评分或消费排名只要有一个候选缺失，该项本轮就不参与比较，不会因此排除渠道。改善幅度按0–100分的分差衡量。

高分优先，同分保留当前渠道。分数是本轮候选之间的相对比较；候选集合变化时分数可能变化，不能视作平台质量评分。模型价格优先不保证最快。

### 候选表格与手动切换

合格候选表展示渠道、倍率、用户评分、模型价格、延迟、成功率、检测状态、消费名次和平台告警。模型价格未知时可查看 1× 渠道价。点击可排序的列名只调整显示顺序，「消费名次」列可按名次升序或降序排列。「未参与比较」汇总排除原因和数量。列表因更换策略标为过时时，手动切换按钮不可用，须等下次检查重新排序。设置最高模型价格后，缺价渠道的明细仍可在此查看。

每张 Key 卡片可开启「排除平台告警」，下次检查会排除有有效告警的渠道，默认关闭。暂停后点「恢复」会沿用当前配置，并从下一次检查继续。

每行提供手动切换按钮，确认窗口明确显示key、绑定模型、原分组和目标。确认后会真实改组，无需勾选自动切换。提交前重新验证账号、当前分组、权限、最新候选及筛选条件；操作后暂停该key的自动选择。结果不明时仍先读回，不盲目重复写入。

### 可自定义规则

这些规则可在默认模板和各 Key 的策略中设置：

- 只选模型检测通过：默认开启。渠道检测状态须为通过，检测模型可以与绑定模型不同。若检测包含糖果题，答案必须为 21，且平台未标记该题失败。平台明确标明检测不适用或未完成时排除。关闭此筛选后，仍要求绑定模型健康和分组可用。
- 最低缓存率（%）：默认0不限制。采用指定模型 `summary_models[model].range_cache.cache_hit_rate` 的 1h 缓存命中率，达到门槛才入选；要求缓存数据就绪、覆盖完整、样本数大于0且刷新时间在5分钟内，缺失或过期时排除。该指标同时展示在候选表中。
- 最低成功率（%）、最低样本数、最高延迟（ms）、最高模型价格、最高账号倍率：默认0，表示不额外限制。设定阈值后，该指标缺失的候选也会被排除。
- 渠道白名单、黑名单：填写分组数字ID，逗号或空格分隔；黑名单优先。
- 连续确认轮数：1–6，默认1；切换冷却：0–1440分钟，默认0。
- 最小改善幅度：0–100，默认0。模型价格模式按价格降低的百分比衡量；综合和自定义模式按0–100分中的分差衡量。
- 检查间隔：全局1–60分钟，默认5；改变间隔会重置所有key的观察计数，包括独立策略。

冷却与最小改善仅限制正常优化；当前渠道不合格时仍按既定规则直接寻找合格候选。没有合格候选保留并提醒。

### 模型目录是否实时

从平台当前目录读取模型名称，去重后排序。分组选入范围以是否列出同名模型为准。点击“读取 key”或配置页的“读取 key 与模型”可刷新，后台每轮检查也会更新目录，打开的配置页每20秒同步后台结果。目录刷新会保留页面当前选择，不会自动替换已经绑定的模型。

平台模型检测与模型健康是两种状态。渠道检测通过时，不要求其检测模型与绑定模型同名；表格会显示实际检测模型。绑定模型的上架、健康与价格仍单独检查。

0.4.x 升级时，已删除的策略换成最接近的策略：账号倍率优先、缓存率优先改为模型价格优先，首响应延迟优先、成功率优先改为对应权重100的自定义策略，其余设置和观察计数保留。首响应延迟优先或成功率优先且最小改善幅度大于0的 key，升级后改善幅度的含义从百分比变为分差，这些 key 会转为只预览并记录提示，需用户确认策略后重新开启自动切换。升级旧配置时保留 key/模型绑定、自动切换开关及待核实操作；因外部改组暂停的监控会恢复，其余暂停状态保留。确认轮数默认为一轮。

模型价格只用于比较渠道，按 Key 设置的用量比例估算；实际请求按平台的计费规则结算。

接口没有已证实的条件更新或事务能力。插件在写入前再次读取当前分组，但极短的跨客户端并发修改仍无法完全避免。
