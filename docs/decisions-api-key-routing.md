### 公开真实数据调研（尚非用户决策）

- OpenRouter《State of AI》（2025 年 12 月，数据主要截至 2025 年 11 月）分析真实请求元数据，报告平均输入超过约 6000 token、输出约 400 token；据此可取约 15:1 作为全站混合工作负载的参考，不代表特定模型或用户实际比例。编程请求输入常超过 20000 token，但报告未在该段给出对应输出均值，不能据此拼接编程比例。
  来源：https://openrouter.ai/state-of-ai （The Anatomy of Prompt-Completion Shapes）
- OpenAI 2026-09-22 公布的客户案例：Manus 报告缓存命中率从约 85% 提升至超过 90%；这是经过优化的长期 Agent 案例，不能视为普遍命中率，更不能保证转售渠道达到同等结果。
  来源：https://openai.com/index/better-prompt-caching-for-gpt-6/
- 调研结论：可参考真实数据设置可调整预设，但未找到可直接代表该用户的输入/输出/缓存读取/缓存写入完整联合画像。需先明确 key 用途；不将不同来源的统计拼接后称为真实单一工作负载。

## 需求收敛摘要（待用户确认开始实现）

- 目标：同一平台内，为用户指定的 key 管理最便宜的合格首选分组；每个 key 固定一个模型，主要用于编程助手／Agent。
- 运行：浏览器运行期间每5分钟检查价格和状态，平台页面可关闭；不要求浏览器关闭后运行。
- 成本：统一可按 key 调整的画像，总输入∶输出=15∶1；输入按普通15%、缓存读取80%、缓存写入5%拆分。按核实后的实际计费规则估算总成本。
- 合格条件：指定模型健康、分组可用、数据未过期；失败、未知、过期候选不参与。
- 正常优化：同一候选连续两轮为最低价才切换，同价保留当前分组。
- 异常分组：当前分组任何不合格时，下一次检查直接切到合格最低价候选；没有合格分组则保留当前并提醒。
- 路由边界：平台内置故障转移保持设置，插件只管理首选分组。
- 手动干预：检测到手动／外部改组则暂停该 key，等用户手动恢复。
- 异常处理：浏览器通知＋插件记录，重复故障去重；读取失败下轮重试、登录失效等重新登录、切换不明先读回核实。

## 排序策略扩展（0.2.0）

- 结论：开放真实价格、首响应延迟、成功率三项，支持单项排序或自定义权重。理由：用户选择精简三项。
- 结论：全局默认策略，逐key可独立覆盖。理由：用户明确选择；默认继续真实价格优先。
- 实现约定：权重0–100且至少一项正值，总和自动换算；指标按本轮合格候选min-max换算为分数，加权高分优先；同分保留当前。价格与延迟低者好，成功率高者好。
- 实现约定：只使用该key指定模型的1h摘要；所需指标缺失、无有效样本或数据过期时排除；权重0的缺失指标不影响资格。健康、可用、权限等硬门槛始终保留。
- 切换逻辑延续两轮确认，目标由最低价推广为策略最优；单项价格模式仍同价不切。当前候选不符合当前策略资格时直接切到合格最优；无合格候选保留提醒。
- 验证：35项测试及独立Edge模拟全流程通过，包含全局权重、逐key覆盖与恢复继承。未改动真实key。
